M.01

Déploiement d'une infrastructure Windows Server (AD DS, GPO)

Contexte

L'entreprise TechNet Solutions souhaite centraliser la gestion de ses postes utilisateurs et de ses ressources via un domaine Active Directory.

Besoins

Mettre en place un contrôleur de domaine basé sur Active Directory. Créer une unité d'organisation pour le service technique. Déployer une GPO pour automatiser la distribution des mises à jour.

Réponse aux besoins

Le rôle AD DS a été installé sur Windows Server. Le domaine technet.local a été créé, ainsi que l'unité d'organisation G_tech. Une GPO a été configurée pour automatiser la distribution des mises à jour Windows aux postes du domaine.

M.02

Mise en place de services Linux (Samba & vsftpd)

Contexte

L'entreprise TechNet Solutions souhaite déployer un serveur Linux sous Debian dédié au partage de fichiers et au transfert FTP, en complément de son infrastructure Windows.

Besoins

Installer et configurer Samba pour le partage de fichiers entre Linux et Windows. Mettre en place vsftpd pour le transfert FTP.

Réponse aux besoins

Une machine virtuelle Debian a été déployée sans interface graphique. Samba a été installé puis configuré dans /etc/samba/smb.conf pour permettre le partage avec les postes Windows. vsftpd a été installé et activé pour le transfert FTP.

M.03

Mise en place d'un serveur DHCP

Contexte

Chez TechNet Solutions, les postes utilisateurs doivent recevoir automatiquement leur configuration IP. Un serveur DHCP unique doit pouvoir servir plusieurs réseaux différents.

Besoins

Mettre en place un serveur DHCP capable de délivrer les adresses IP automatiquement. Permettre à ce serveur DHCP de fonctionner sur plusieurs VLAN, car par défaut les requêtes DHCP ne traversent pas les routeurs.

Réponse aux besoins

Un serveur DHCP a été configuré pour délivrer les adresses du réseau 172.16.10.0/24. Sur les routeurs Cisco, la directive ip helper-address 172.16.10.1 a été ajoutée sur les sous-interfaces des autres VLAN pour relayer les requêtes DHCP vers le serveur central.

M.04

Routage OSPF entre plusieurs routeurs

Contexte

L'infrastructure de TechNet Solutions évolue : plusieurs routeurs doivent communiquer entre eux pour relier les différents sites de l'entreprise.

Besoins

Interconnecter plusieurs routeurs entre eux. Permettre la propagation automatique des routes entre les routeurs via le protocole OSPF. Assurer que chaque routeur connaisse l'ensemble des réseaux disponibles.

Réponse aux besoins

Les routeurs ont été configurés avec OSPF en zone unique (area 0). Les réseaux d'interconnexion et les VLAN ont été annoncés sur chaque routeur. La connaissance des routes est désormais propagée automatiquement entre tous les routeurs.

M.05

Communication entre VLAN d'un même site

Contexte

Au sein du même site de TechNet Solutions, plusieurs services sont segmentés en VLAN différents. Les utilisateurs ont besoin que ces VLAN puissent communiquer entre eux tout en gardant l'isolation logique.

Besoins

Faire en sorte que les VLAN communiquent entre eux, c'est-à-dire qu'un poste du VLAN 10 puisse joindre un poste du VLAN 20. Configurer les sous-interfaces des routeurs pour permettre ce dialogue.

Réponse aux besoins

Sur les routeurs, des sous-interfaces ont été créées, une par VLAN. Chaque sous-interface joue le rôle de passerelle pour son VLAN. Les commutateurs ont été configurés en mode access sur les ports utilisateurs et en mode trunk sur les liens montants pour transporter tous les VLAN.

M.06

Routage inter-VLAN

Contexte

Les services administratif et technique de TechNet Solutions sont sur des VLAN différents et doivent pouvoir communiquer entre eux via un routeur central.

Besoins

Mettre en place un routage inter-VLAN, c'est-à-dire que les VLAN communiquent entre eux à travers un seul routeur. Permettre le passage des VLAN entre les commutateurs via un lien trunk.

Réponse aux besoins

Deux VLAN (10 et 20) ont été déclarés sur les commutateurs. Les ports utilisateurs ont été configurés en mode access, le lien d'interconnexion entre commutateurs en mode trunk. Sur le routeur, deux sous-interfaces (g0/0.10 et g0/0.20) ont été créées pour servir de passerelles aux deux VLAN.

M.07

Architecture multi-sites + ajout d'un SSID Wi-Fi

Contexte

L'infrastructure de TechNet Solutions doit intégrer plusieurs sites distants avec leurs propres VLAN, et ajouter un point d'accès Wi-Fi diffusant un nouveau SSID pour les utilisateurs.

Besoins

Mettre en œuvre une architecture multi-sites avec plusieurs VLAN. Centraliser le DHCP. Ajouter un SSID Wi-Fi sur le réseau pour permettre aux utilisateurs de se connecter sans fil.

Réponse aux besoins

L'architecture a été déployée avec plusieurs routeurs Cisco reliés par des liaisons de transit. OSPF a été activé sur tous les routeurs. Le DHCP relais (ip helper-address) a été configuré pour relayer vers le serveur central. Un point d'accès Wi-Fi a été ajouté pour diffuser un SSID accessible aux utilisateurs.

M.08

HSRP — Redondance haute disponibilité

Contexte

L'infrastructure de TechNet Solutions repose sur des passerelles uniques. En cas de panne d'un routeur, le site est isolé. La direction souhaite une solution de haute disponibilité.

Besoins

Garantir la continuité de service en cas de panne. Mettre en place une redondance de passerelle avec basculement automatique. Conserver une seule IP virtuelle pour les postes. Bascule en moins de 15 secondes.

Réponse aux besoins

Le protocole HSRP a été déployé sur deux routeurs Cisco 2911. Deux groupes HSRP : Groupe 1 IP virtuelle 10.0.10.254, Groupe 2 IP virtuelle 10.0.11.254. Priorités configurées (R1 : 101, R2 : 102) avec standby preempt. Bascule testée : moins de 15 secondes sans perte de session.

M.09

Architecture avec switches niveau 3

Contexte

TechNet Solutions souhaite faire évoluer son infrastructure réseau pour qu'elle soit plus performante. À la place de routeurs séparés, on utilise des switches niveau 3 (multilayer switches) qui font à la fois la commutation (couche 2) et le routage (couche 3).

Besoins

Mettre en place une architecture basée sur 4 switches niveau 3. Activer le routage IP sur ces switches. Maintenir le routage OSPF entre les équipements. Garantir la redondance avec HSRP. Centraliser le DHCP avec un relais.

Réponse aux besoins

Quatre multilayer switches Cisco 3560 ont été configurés avec la commande ip routing pour activer le routage. Chaque switch porte plusieurs VLAN et des interfaces SVI (Switched Virtual Interface, int vlan X) qui servent de passerelles. HSRP a été configuré sur les VLAN 10, 20 et 21 avec des IP virtuelles 172.16.X.250. Le relais DHCP a été configuré sur chaque interface VLAN. OSPF propage les routes entre tous les switches.
